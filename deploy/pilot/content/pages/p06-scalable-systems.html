A service that works for ten users can fail for ten thousand. Scalability is the ability to handle more load by adding resources. Vertical scaling gives a single machine more memory or processors. Horizontal scaling adds more machines and places a load balancer in front of them to share the requests between them.

Spreading work over many machines creates new problems. Messages can arrive late, out of order or not at all, and any machine may fail at any moment. A fault-tolerant design expects this: it keeps several copies of the data, retries failed requests with increasing delays and stops sending traffic to a server that does not answer.

Concurrency means that many operations are in progress at the same time. Two requests that change the same record can overwrite each other unless the system uses locks, transactions or a careful ordering of updates. Queues help by letting a busy service accept work now and process it a little later.

Performance is measured, not guessed. Engineers record response times and error rates, find the slowest step and improve it, then measure again. Caching frequently read results close to the user is often the cheapest improvement.
