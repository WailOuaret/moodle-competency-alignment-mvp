A relational database stores data in tables made of rows and columns. Each row is identified by a primary key. A foreign key in another table points back to it, which is how a table of orders refers to the customer who placed them. Designers split data across tables to avoid repeating it, a process called normalisation.

The language used to ask questions is SQL. A SELECT statement chooses columns, a WHERE clause keeps only the rows that match a condition, and ORDER BY sorts the result. A JOIN combines rows from two tables that share a key, for example every order with the name of its customer.

To summarise data, GROUP BY puts rows into groups and aggregate functions such as COUNT, SUM and AVG compute one value per group. Adding HAVING filters the groups themselves, for example only the customers with more than five orders. Subqueries and views make longer questions easier to read and to reuse.

Transactions keep a database consistent. A transfer between two accounts either completes entirely or not at all, even if the system fails half way. Indexes speed up searches at the cost of some extra storage and slower writes, so they are added where queries need them.
